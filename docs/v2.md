# v2 extension points

v2 adds lesson balances in D1 and bot commands. The MVP is laid out so that most of it is new modules.

## Storage

- Add a D1 binding in `wrangler.jsonc`, repositories in `src/db/` and SQL in `migrations/`.
- `makeOnPaymentReceived` in `src/app/onPaymentReceived.ts` gains a repository dependency. It is the one place that changes
  for dedupe, student matching and balance updates.
- `src/http/stripeWebhook.ts` (signature check) and `src/stripe/verify.ts` stay unchanged. `src/notify/telegram.ts` and the
  `Notifier` port changed in v2.1a: `send(text, opts?)` takes buttons and returns the `message_id`.

## Student match

Superseded by v2.1a: there is no `client_reference_id` or per-student Payment Link. A Payment is matched by the Payer
email stored in `payer_emails`; an unknown email goes to the picker in Telegram.

Use `source.clientReferenceId` (a per-student Payment Link with `?client_reference_id=<student>`) or
`source.metadata.student_id`. Both are already carried on `PaymentReceived`.

## Pack size

Superseded by v2.1b: the Payment Link id maps to a product name and lesson count in `src/domain/products.ts` (no env var, no
Stripe metadata). The Pack size is stored on the Payment row as `payments.lessons` at record time.

`checkout.session.completed` does not include line items. Put `lessons` in the Payment Link or session metadata.
Otherwise v2 needs a restricted Stripe API key and a client built with
`new Stripe(key, { httpClient: Stripe.createFetchHttpClient() })` to fetch the line items.

## Idempotency

Superseded by v2.1a: payments are deduplicated by checkout session id (a unique column on `payments`), not by event id,
and the `credits` table below was not built. In v2.1b a Credit is `payments.lessons` on an assigned row, so the dedupe
is the same unique column; Adjustments live in the `adjustments` table and the Balance is their sum plus the Credits. The `notified_at` idea was kept: a retry after a Telegram failure resends the
message without storing the Payment twice.

The MVP accepts duplicate messages on Stripe retries. For v2 the agreed option (decisions.md) is to dedupe by event id.

Proposal, for the user to decide: key the ledger by checkout session id instead, so one payment is one credit even if Stripe
sends a second paid event for the same session:

```sql
CREATE TABLE credits (
  checkout_session_id TEXT PRIMARY KEY,
  student_id TEXT NOT NULL,
  lessons INTEGER NOT NULL,
  notified_at TEXT
);
INSERT INTO credits (checkout_session_id, student_id, lessons) VALUES (?, ?, ?) ON CONFLICT DO NOTHING;
```

Balance = `SUM(credits.lessons) - COUNT(lesson_uses)`. Retries are idempotent by construction. `notified_at` lets a retry after a
Telegram failure send the message again without crediting twice. A D1 failure maps to the existing 500 `processing failed` row.

## New event families

Refunds (`charge.refunded`) and `checkout.session.async_payment_failed` need a mapping and handler change in
`src/stripe/toPayment.ts` and `src/http/stripeWebhook.ts`. They are not covered by the "unchanged in v2" list above.

## Bot commands

Superseded by v2.1a where noted: the route, `TELEGRAM_WEBHOOK_SECRET` and the secret-token check were built as described.
There is no `TELEGRAM_OWNER_ID` and no restriction by `ctx.from.id`: any member of the configured chat may use commands, and
updates from other chats are ignored. `/used` is not built yet. The `Notifier` port did change (see Storage).

- Add `src/bot/` with a grammY `Bot` and `webhookCallback(bot, "cloudflare-mod", { secretToken })`, served at
  `/telegram/webhook`. grammY then verifies the `X-Telegram-Bot-Api-Secret-Token` header.
- Add env vars `TELEGRAM_WEBHOOK_SECRET` and `TELEGRAM_OWNER_ID`.
- Restrict commands to the owner by `ctx.from.id`, not only by chat id, because the chat may be a group.
- Mark a lesson as used with a `/used <student>` command. Inline buttons would add an optional `send(text, opts?)` parameter
  to `Notifier`, which is additive.
- A balance-aware message is a new formatter in `src/app/messages.ts`.
- Add the route in `src/worker.ts`; the `/stripe/webhook` contract is unchanged.
